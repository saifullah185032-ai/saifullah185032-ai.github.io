OVERVIEW

Answers you can check.

The problem. Language models do not know your private documents, and when they do not know something they often answer anyway. For technical support and enterprise work, a confident wrong answer is worse than no answer. Pasting whole manuals into a prompt does not scale either.

The approach. RAGForge finds the few passages that matter, gives only those to a local language model, and requires it to answer from them and cite them. If nothing relevant is found, the model is not called at all. Every answer comes with its sources, so a person can verify it.

CAPABILITIES

What it does

01

Ingestion

Loads .txt and Markdown files and splits them into overlapping chunks that respect word boundaries. For Markdown, every chunk records the heading it belongs to, which later becomes the citation (for example "Guide > Cleaning schedule").

02

Local embeddings

Turns text into vectors with a local Ollama model, in batches, with clear errors when the server or model is missing. Cosine similarity is implemented from first principles and covered by tests.

03

Swappable vector store

An in-memory store for zero-setup use, and a Qdrant adapter over its REST API for persistence. Chosen by one configuration setting. Re-uploading a file replaces the old version instead of duplicating it.

04

Hybrid retrieval

Semantic search finds meaning; BM25 keyword search finds exact tokens such as error codes. The two rankings are merged with Reciprocal Rank Fusion, which uses ranks only, so their score scales never need to match. Optional LLM reranking improves precision.

05

Grounded answers with citations

A strict prompt tells the model to use only the numbered passages and to say it does not know otherwise. The response lists every passage shown to the model and marks which ones the answer actually cited.

06

Measured quality

A built-in evaluation endpoint reports HitRate@K and Mean Reciprocal Rank for a set of test questions, so each change (chunk size, hybrid mode, reranking, model) is judged by numbers.

HOW IT WORKS

Two pipelines.

Everything in the system is one of these steps, or a measurement of how well they work.

  ↓ embedding model (Ollama)

ARCHITECTURE

Four layers, one rule.

The code is split into Domain (plain models and math, no packages), Application (the use cases and the interfaces they need), Infrastructure (Ollama, Qdrant, BM25, loaders) and Api (HTTP).

The dependency rule: arrows point inward. Application never mentions Ollama, Qdrant or HTTP. Every external capability sits behind an interface, so a technology is replaced by adding one class and changing configuration.

Dependency direction

Api ──────────→ Application ──→ Domain
 │                   ↑
 └─→ Infrastructure ─┘
     (implements the interfaces)

DECISIONS

Engineering choices, and why.

RETRIEVAL

Reciprocal Rank Fusion instead of blending scores

Cosine similarity and BM25 live on incompatible scales

  • Fusing by rank needs no tuning per document set and stays deterministic.
SAFETY

Never call the model when nothing relevant is found

A model that is not asked cannot hallucinate

  • The answer is an explicit "nothing found" result, and the prompt gives the model an exact "I don't know" sentence when the passages are insufficient.
DATA

Document identity comes from the file name

Re-uploading replaces; it never duplicates

  • Embedding happens before the old version is deleted, so a failed embedding never destroys existing data.
RESILIENCE

One error type per dependency, one place that maps them to HTTP 503

Messages say what to do: "Is it running?", "ollama pull gemma3:4b"

  • A failing reranker falls back to the original order instead of breaking search.
OPERATIONS

Keyword index rebuilt from the vector store at startup

Hybrid search works immediately after a restart

  • Verified against a real Qdrant server, including paged scrolling of stored chunks.

Unit tests use small hand-written fakes and stubbed HTTP handlers, so the whole suite runs without Ollama or Qdrant. The Qdrant adapter was additionally exercised against a real Qdrant server. Retrieval quality is measured with the evaluation endpoint rather than judged by eye.

HONEST LIMITS

What it does not do yet.

Scale. The in-memory store and the BM25 index scan every chunk: fine for thousands of chunks, not millions.

Formats. Only .txt and Markdown today. A PDF loader with page-number citations is the next planned step.

Security. No authentication yet, and documents are treated as trusted input. A production deployment needs access control, per-user filtering before retrieval, and defences against prompt injection.

Evaluation. It measures retrieval, not answer faithfulness. An LLM-judged faithfulness check is a planned extension.
